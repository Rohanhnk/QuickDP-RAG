Event-Driven Agentic Doc Workflows 📓

notes — the level after plain RAG
the big idea

RAG retrieves the info — the agentic workflow orchestrates the whole multi-step task around it (parsing, questions, answers, review, retries...).

1. Must-know concepts

  • Agentic workflow — AI does multiple steps to finish a task, not just one shot
  • Event — a signal that "something happened", can trigger the next step
  • Workflow step — one single unit of work inside the workflow
  • RAG — retrieve relevant doc info before answering (same as before)
  • Vector store — holds embeddings for semantic search
  • Query engine — the interface that actually searches the indexed docs
  • Human-in-the-loop (HITL) — a person reviews / corrects / approves the output
  • Structured output — predictable, machine-usable result (not free text)

2. Intermediate ideas

Branching → workflow picks different paths depending on the result so far

Looping → a step repeats if the answer is wrong/incomplete/needs feedback

Concurrent execution → independent tasks run without waiting on each other

Event collection → a later step waits for several events before continuing

Async execution → long tasks run without blocking unrelated work

doc → questions → RAG query → answers → structured output

3. the architecture — mental picture

SOURCE DOCUMENT ↓ parse / index doc ↓ embeddings + vector store ↓ query engine ↓ form → parse fields → generate questions ↓ RAG query → retrieve info → generate answer ↓ HUMAN REVIEWS OUTPUT ↙ ↘ correct incorrect ↓ ↓ continue feedback → re-process

remember: RAG retrieves the info, the agentic workflow runs the whole show

4. event-driven vs sequential

plain pipeline: A → B → C → D (rigid, one path)

event-driven: A → event → B → event → C → event → D

each step fires an event, and that event is what wakes up the next step. Much more flexible than a fixed pipeline.

5. branching / looping / concurrency

  • Branching — if condition met → path A, else → path B
  • Looping — answer → human review → feedback → re-answer → review (repeat)
  • Concurrency — Q1, Q2, Q3, Q4 all run RAG in parallel → then collect → final output
independent questions = run together dependent steps = must run in order

6. interview Q&A — quick answers

Q: What's an agentic workflow?

AI does multiple steps to finish a task — decides actions, uses retrieval/tools, checks results, keeps going till done.

Q: Event-driven architecture?

Components respond to events. One step produces an event → that event triggers another step.

Q: Why events (not just a fixed pipeline)?

Agentic apps need branching, loops, async work, concurrency — events are a clean way to wire all that together.

Q: Agentic doc workflow vs simple RAG?

Simple RAG = retrieve → context → answer. Agentic workflow = parsing + question gen + retrieval + answering + validation + feedback + retries — the whole task.

Q: Why human-in-the-loop, why not full autonomy?

Humans catch wrong/incomplete output before it becomes the final result — a validation layer, matters most where accuracy is critical.

Q: Sequential vs concurrent — when which?

Sequential — when one task needs another's result first (parse doc → then generate questions).
Concurrent — when tasks are independent (answering unrelated questions).

Q: Main takeaway of the course?

Move from simple RAG → event-driven agentic system: multi-step, branches, loops, concurrent work, + human feedback.
